# Verification

"Built and tested" means a skeptical reviewer can reproduce every claim of correctness from a clean clone. This file defines what is tested, how, to what threshold, and how evidence is recorded.

## 1. Strategy

1. **Spec-derived tests:** every normative statement in `SPEC.md` has at least one test, tagged `# spec: §6` (Python) or `// spec: §6` (TS). A script (`scripts/spec_coverage.py`) lists spec sections without tests; zero is required.
2. **Golden vectors:** numeric truth lives in `spec/vectors/*.json`, generated by the Python reference and committed. Both languages consume them. `make vectors-check` regenerates and fails on any diff. Vectors change only with a spec change recorded in an ADR.
3. **Property tests** for invariants (Hypothesis, fast-check).
4. **Independent oracles** wherever one exists: sympy for Boolean minimization, scipy for `Φ`, published worked examples for Krippendorff's α, hand-computed examples for scores.
5. **Recovery tests:** the simulator plants known ground truth; the pipeline must recover it (a test of the whole measurement chain).
6. **Mutation testing** on the core to prove the tests can fail.
7. **End-to-end and accessibility tests** on the built site.

## 2. Invariants (property tests, Python and TS)

| Area | Invariant |
| --- | --- |
| Gray / grid | `gray` is a bijection on 0..15; consecutive positions (with wrap) differ by one bit; 256 pixel IDs ↔ (col,row) ↔ bits is a bijection; each pixel has 8 single-flip neighbors, exactly 4 grid-adjacent |
| Assignment | Mass sums to 1 (within `1e-12`) before and after pruning; each `p_i ∈ [0,1]`; `σ → 0` yields one-hot mass at the threshold-determined pixel; raising `μ_i` never lowers `p_i` |
| Net effects | `HNE, SNE ∈ [−1,1]`; HNE is monotone non-decreasing in each `s_i`; `outcome_available=false` caps tier at E1 |
| SQ | `SQ ∈ [−100,100]`; `S ∈ [0.5,1]`; `C < 0 ⇒ S_eff = 1` (SQ independent of stability); raising HNE never lowers SQ; gate never raises SQ; with gate `G` and `C<0`, `SQ = SQ_raw` unless `SQ_raw > 100G`; non-compensation: when `HNE < 0`, increasing SNE never changes SQ |
| Classes | Function is total over the 9 cells; boundaries at ±0.2 behave as specified (`> 0.2` is +); `operator_blind` never yields Parasitism |
| Zones | Exactly one primary zone for every input; precedence is respected; boundary values (−25, 25, 60) map as specified; a confirmed gate always yields Z7 |
| Cover | Every returned rule is admissible; coverage ≥ target or the solver reports infeasibility explicitly; unobserved cells contribute zero mass; strict mode functionally equals the Boolean harm function on observed cells; result is deterministic per seed |
| Counterfactual | Observed neighbors take precedence over modeled; `ΔSQ` sign convention consistent |
| Temporal | Trajectory is negative only when two consecutive drops each exceed MDC |
| Privacy | `n_eff < k_min ⇒ SQ = null` in public artifacts; withdrawn-consent records never appear in any export |
| Determinism | Same inputs, config, seed ⇒ byte-identical artifact bytes and hashes |

## 3. Cross-language parity

`packages/ts` must reproduce Python outputs on every golden vector within tolerance: `1e-9` absolute for `Φ`, mass, net effects, and SQ; exact equality for pixel IDs, classes, and zones. Include **boundary-hugging** vectors (values within `1e-12` of thresholds) and 200 randomized portal response sets generated with a fixed seed. Parity tests run in CI on both Node LTS and the minimum supported Node.

## 4. Thresholds

| Gate | Threshold |
| --- | --- |
| Python line / branch coverage (core modules) | ≥ 95% / ≥ 90% |
| TS line / branch coverage (core) | ≥ 95% / ≥ 90% |
| Mutation score (core) | ≥ 80% (mutmut, Stryker); surviving mutants reviewed and logged |
| Types | `mypy --strict` and `tsc --strict` with zero errors; zero `Any`/`any`, zero ignore comments (CI greps) |
| Lint | `ruff`, `eslint`, `stylelint`, `markdownlint`, `vale`, `codespell`: zero warnings |
| Spec coverage | 100% of normative sections tagged |
| Links | `lychee`: zero broken internal links; external failures reviewed |
| Accessibility | axe-core: zero violations on every built page and key portal states; Lighthouse accessibility 100 |
| Performance | Budgets in `07_UX_RULES.md` §8 |
| Security | `pip-audit`, `npm audit` (no high/critical), CodeQL clean, `gitleaks` clean, SBOM generated |
| Reproducibility | `make repro` hashes equal to committed hashes |

Thresholds may be raised, never lowered, without an ADR approved by a maintainer other than the author.

## 5. Test catalogue by milestone

- **M1:** worked-example tests computing each intermediate value of GV-SQ-001..003; all 16 Gray positions; all zone and class boundaries; assignment edge cases (σ at floor, μ = θ, p = 0 or 1).
- **M2:** 6561-rule enumeration count; purity and coverage hand examples; planted-cover recovery (a known rule must be returned); strict-mode agreement with sympy on ≥ 500 random functions across sizes and don't-care densities; infeasible-target behavior; tie-break determinism; runtime budget.
- **M3:** all vectors in TS; `erfc` against scipy on a dense grid including tails; bundle-size check.
- **M4:** no raw text on disk (instrumented I/O test); consent exclusion; suppression; DP mechanism moment tests with fixed seeds (mean and variance within tolerance over 10⁵ draws); signature round trip and tamper detection.
- **M5:** Krippendorff's α against published worked examples (nominal, ordinal, interval); judge harness rejects an unreliable judge; sycophancy twin generator produces pairs differing only in stated stance (checked by diff); simulator recovery tests (planted H/M trajectories recovered within stated tolerances); content scanners confirm no prohibited text in fixtures; `sweep` reproducibility.
- **M6:** Card built only from artifacts (a test mutates an artifact and expects the Card to change); tiering tests with planted differences; critical-event exclusion from the top tier; PDF accessibility check (tags, title, language).
- **M7–M8:** Playwright suites: keyboard navigation of the map (arrow keys, wrap, Home/End, PageUp/PageDown), pin/unpin, neighbors panel, resolution switching, table alternative parity with the map data, reduced-motion behavior, forced-colors rendering, print stylesheet snapshot; portal full flow with "Prefer not to say" paths; **assert zero network requests** beyond same-origin static assets; assert no `localStorage` writes unless the user opts in; visual regression at 360, 768, 1280 px, light and dark.
- **M9:** reference verifier script checks every `references.bib` entry has `x-verified: true` and a resolvable DOI or URL (run manually with network, recorded in build log); content claims registry coverage; Vale clean.
- **M10:** clean-clone `make verify` on a second machine; release checklist.

## 6. Manual verification (cannot be automated; record in build log)

- Hand reproduction of GV-SQ-001 by a human reviewer from the spec text.
- Screen reader passes (NVDA, VoiceOver) across home, map, portal, and a docs page.
- Keyboard-only run of the complete portal.
- 200% and 400% zoom; 360 px width.
- Color-vision-deficiency simulations of the map in all three modes.
- Expert read of the whitepaper and all public copy for overclaiming.
- Review of every `OPEN_QUESTIONS.md` entry with a decision recorded.

## 7. CI workflows

| Workflow | Triggers | Jobs |
| --- | --- | --- |
| `ci.yml` | PR, push | lint, py tests (matrix: min and max supported Python), ts tests (min and max Node), parity, vectors-check, build, e2e + axe, perf (LHCI), links |
| `mutation.yml` | nightly, release | mutmut, Stryker |
| `security.yml` | PR, weekly | pip-audit, npm audit, gitleaks, CodeQL, dependency review, SBOM |
| `scorecard.yml` | weekly | OpenSSF Scorecard |
| `pages.yml` | push to `main` | build and deploy site |
| `release.yml` | tag `v*` | build wheels/sdist and npm pack, generate SBOM and checksums, create release notes, attach artifacts; publishing steps require maintainer approval |
| `repro.yml` | weekly | `make repro` on a clean runner |

All third-party Actions pinned by commit SHA; least-privilege `permissions:` blocks; branch protection on `main` requiring all checks and one review.

## 8. Acceptance checklist for v0.1.0 (each item needs evidence: a log, a file, or a recording)

**Specification and math**
- [ ] Every normative spec statement has a tagged test
- [ ] GV-SQ-001..003 reproduced by code and by a human
- [ ] Gray, grid, neighbors verified exhaustively
- [ ] Strict-mode MFC equals sympy on 500+ random cases
- [ ] Python and TS parity within tolerance on all vectors
- [ ] No numeric constants in source outside the config

**Pipeline and data**
- [ ] Planted ground truth recovered by the sweep
- [ ] `make repro` hashes match
- [ ] Manifests signed and verified; tampering detected
- [ ] No raw text stored; consent exclusion proven; suppression proven

**Site and portal**
- [ ] Every page passes axe, Lighthouse, and keyboard checks
- [ ] Zero third-party requests; zero network requests in the portal
- [ ] Every number on the site traces to an artifact; every claim has a registry ID
- [ ] Evidence tier visible wherever a result appears
- [ ] Portal wording reviewed: non-diagnostic, conditional, privacy line present
- [ ] Design plan and self-review committed; screenshot matrix attached

**Research and organization**
- [ ] All displayed references verified; prior-art table complete and factual
- [ ] Whitepaper has limitations and no empirical results
- [ ] Governance documents contain no invented people, entities, or legal claims
- [ ] `ORG_FACTS.yaml` complete or explicitly marked unverified and not rendered

**Release**
- [ ] Clean clone passes `make verify` on a second machine
- [ ] Security scans clean; SBOM attached
- [ ] CHANGELOG, release notes, `CITATION.cff` complete
- [ ] `OPEN_QUESTIONS.md` has no blocking item
- [ ] Human reviewer sign-off recorded

## 9. Evidence format

In the build log, evidence is verbatim command output with the command, date, git SHA, and tool versions. Screenshots are committed under `docs/build-log/assets/`. A statement such as "all tests pass" without output is invalid.
